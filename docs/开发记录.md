## 5. 踩过的坑(重要,避免重犯)

### 5.1 `D:\AndroidDev\tap.ps1` 的两个致命缺陷

1. **精确文本匹配会静默跳过**:按钮文字带计数(如 `下一格(1/3)`)时,
   `-Keys '下一格'` 永远匹配不到 → 脚本**跳过该步** → 之后的所有结论都不可信。
   已加前缀回退。**看到 `[!! 跳过]` 必须停下查工具,不要接着推断应用有 bug。**
2. **前缀回退会点错节点**:`x` 既是键盘键、又是面板字段格的显示值(精确相等),
   会点到字段格上。已加规则:候选同含键盘区(y > 1400)与面板区时**优先键盘区**,
   且该规则必须放在精确匹配**之外**。

### 5.2 结构改动用括号计数,不要靠缩进猜

本会话有 6 次在「挪代码块」上失败(漏闭合 `Box`、插到错误层级、
按缩进猜闭合行差一行、删开启留闭合导致深度 -1……)。
**有效做法**:先用逐字符括号计数定位目标行,每步验证括号深度为 0。
最后清理嵌套 `Box` 时用这招,一次成功。

### 5.3 在已滚动的父容器里放滚动子容器,必须给**确定高度**

- `heightIn(max = N)` 在无界约束下**无效** → 内容被裁掉,滚也滚不动
- `height(N)` + `verticalScroll` 才有效
- 症状:面板底部按键「看不到、点不到」(矩阵编辑器的 `关闭/平方/立方/Abs` 曾因此消失)

### 5.4 新增函数要改**两处**

`Lexer.FUNC_ALIAS`(函数名白名单)与 `MathFns`(实现)必须同时改,
否则解析阶段报「未知名称」。无参函数(`ran`)还不能走 `PAREN_FUNCS` 那条路。

### 5.5 测试设计比实现更容易出错

本会话累计 **8 次**是「我的断言写错」而不是实现错,典型:
- 用 `1/2x` 在 x=3 时验证 `1/(2x)` —— 两种语义**恰好都等于 1.5**,无判别力
- 用奇次幂验证高斯规则精确性 —— 奇函数在对称区间积分**本来就是 0**
- 断言显示串而非数值(`rnd(123456789012)` 实际显示成科学计数法)
- 嵌套 `?:` 让 `up()` 被多调用一次
- 手算联立方程解错两次

**规则**:代数/统计类断言**先把解代回原式验算**再写期望值;能比数值就不用比显示串。

### 5.6 推送到 GitHub 的 TLS 问题

本机 `hosts` 把大量 github 域名劫持到 127.0.0.1,真实 IP 的 22/443 也不通;
只有 `ssh.github.com:443` 通。**开 Watt Toolkit 后 HTTPS 可用**,但 git 会报:
`CRYPT_E_NO_REVOCATION_CHECK`(代理做 TLS 中间人)。

**临时做法(不写持久配置)**:
```bash
git -c http.sslVerify=false push
```
`gh` CLI 走系统证书库,不受影响(可以直接 `gh release create`)。
